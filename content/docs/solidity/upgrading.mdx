---
title: Upgrading from v0.1.0
description: Move a target from solidity-sdk v0.1.0 to v0.2.0, the version the router serves.
---

import { Callout } from "fumadocs-ui/components/callout"

The router serves only targets built on
[solidity-sdk v0.2.0](https://github.com/gas-killer/solidity-sdk/releases/tag/v0.2.0).
A v0.1.0 target signs a different digest and settles a different program
format, so the router refuses its tasks. Redeploy it on v0.2.0.

<Callout type="warn">
  A deployed contract can't be patched into v0.2.0. If yours is upgradeable,
  upgrade its implementation. Otherwise deploy a new one and move its state
  across, then point your clients at the new address.
</Callout>

## What changed

| | v0.1.0 | v0.2.0 |
| --- | --- | --- |
| `IGasKillerSDK` id | `0x82b35a01` | `0x57a9b002` |
| `IGasKillerSDKBatch` id | `0xce8e6efc` | `0xe40b0195` |
| `verifyAndUpdate` | 8 arguments, the first the digest | 7 arguments; the contract rebuilds the digest |
| Signed digest | `transitionIndex, address(this), …` | `transitionIndex, block.chainid, address(this), …` |
| Wrong ETH sent, or a changed payload | `InvalidSignature` | `InvalidQuorumSignature` |
| Protected storage | none | the SDK's own slots, plus [any you declare](/docs/solidity/protection#protected-storage) |
| Calls to the contract itself | allowed | [rejected](/docs/solidity/protection#restricting-calls) unless allowed by selector |
| External reads | not checked at settlement | [pinned](/docs/solidity/protection#pinned-observations) and re-checked |

You never encoded `verifyAndUpdate` yourself: the router builds the payload, so
nothing changes in your API client. The work is on the contract side.

## Steps

1. **Move the SDK to v0.2.0:**

   ```bash
   forge install gas-killer/solidity-sdk@v0.2.0
   ```

   Keep `evm_version = "cancun"` or later.

2. **Declare your privileged slots.** If the contract has an owner or other
   control state, override `_protectedRanges()` with its slots. See
   [Protected storage](/docs/solidity/protection#protected-storage).

3. **Allow your self-calls.** If a tracked function calls `this.foo()` or
   `try this.foo()`, override `_allowSelfCall` to allow exactly those selectors.
   Otherwise those transitions revert with `SelfCall`, and because the counter
   only advances on settlement, every later transition waits behind them.

4. **Check your tracked functions still settle.** A tracked function that
   natively changes the SDK's configuration or a slot you protect now fails with
   `ProtectedSlotWrite`. Move that change into a function you call directly.

5. **Redeploy, then verify** the new deployment reports the v0.2.0 interface:

   ```bash
   cast call "$TARGET" "supportsInterface(bytes4)(bool)" 0x57a9b002 --rpc-url "$RPC_URL"
   ```

   Then run the rest of the
   [deployment checks](/docs/solidity/integrate#deploy-and-verify).

If you check digests off-chain, add `block.chainid` after `transitionIndex`, or
call `getMessageHash` on the deployed contract.
